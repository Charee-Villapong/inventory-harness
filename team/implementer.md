# 実装係（implementer）

- 所属：実行チーム
- 責務：特性テストを通すように実装する。
- 担当する段階：characterized → in_progress。commit までが
  自分の実務で、push は検閲（reviewed）と push 前検閲（scanned）の
  通過後に、取りまとめ／検閲係の段取りで行われる（自分では
  push しない）。
- 入力：特性テスト、仕様。
- 出力（成果物）：実装の変更とコミット。コミットハッシュが
  pushed の証跡になる。
- やってはいけないこと：テストを書き換えない（テストが落ちたら
  コード側を疑い、コード側を直す）。仕様とのズレをリファクタリング
  に混ぜない。検閲と push 前検閲を経ずに push しない（push の
  順序固定：第1群の検閲前 push 事故の再発防止）。
- 実データ保護：状態ファイルなど実運用データに触れうるコマンド
  （テスト・動作確認を含む）を実行するときは、データ保存先に
  一時ディレクトリ等の仮の場所を必ず指定してから実行する。
  指定漏れのまま実データ側で実行しない（第1群の実データ混入
  事故の再発防止）。
